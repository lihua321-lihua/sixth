# 学校自由输入 + 来源发现与自定义

## Context（背景）

当前工具把学校写成固定常量「北华航天工业学院」，4 个抓取来源也硬编码在 `constants.ts` 的 `SOURCES` 里，`/select-school` 仅提供单校白名单下拉框。

本次需求要把它改成通用的多校工具：

1. 学校名称改为**用户自由输入**（不再固定、不再白名单）。
2. 登录后**引导用户输入学校**。
3. 用户输入学校后，**用 AI 生成与之相关的网页候选**（用户已确认：用现有 DeepSeek 替代真实搜索 API，并接受「单篇网页 URL」作为来源模型——即一个来源 = 一个 URL，抓取时该页作为一条内容）。
4. 用户勾选候选后**添加为来源**。
5. 用户可**手动新增/删除来源**。

数据模型上引入「每用户来源表」`sources`，抓取流水线从读硬编码 `SOURCES` 改为读用户自己的来源。来源模型遵循用户选择：**单篇网页 URL，一页一条**（不做列表页多链接展开）。

已知取舍（已在需求里确认）：AI 生成的 URL 可能存在错漏，因此保留「手动添加」作为兜底；单页模型下每条来源只产出一条内容。

## 数据模型（新迁移 `00005_add_sources.sql`）

新增 `sources` 表（每用户一行一个来源）：

- `id uuid pk default gen_random_uuid()`
- `user_id uuid not null references auth.users(id) on delete cascade`
- `name text not null`（来源名称）
- `url text not null`（单篇网页 URL）
- `created_at timestamptz not null default now()`
- `unique (user_id, url)`
- 开启 RLS，并加 select / insert / delete 三条 policy（`auth.uid() = user_id`）

同时给 `source_runs` 增加 `name text`（可为空，用于邮件/状态展示，避免回查来源表）：
`alter table public.source_runs add column name text;`

来源身份约定（贯穿改动）：
- `sources.id` = 唯一 key，写入 `source_runs.source`（uuid，稳唯一）。
- `sources.name` = 展示名，写入 `source_runs.name`、`items.source`。

## 后端改动

### 1. `src/lib/constants.ts`
- 删除：`SCHOOL_NAME`、`SCHOOL_SHORT`、`SCHOOL_OPTIONS`、`SourceKey`、`Source` 接口、`SOURCES`、`sourceByKey`。
- 保留并微调 `DEFAULT_INCLUDE_KEYWORDS`（去掉「华航」「北华航天工业学院」两个校名专属词，其余保留为通用默认，用户可改）。

### 2. 新增 `src/lib/types.ts` 类型
- `UserSource { id: string; name: string; url: string; created_at: string }`。
- `DashboardInitial` 增加 `sources: UserSource[]`。
- `SourceRun` 增加可选 `name?: string | null`。

### 3. 新文件 `src/lib/crawler/discover.ts`
- 导出 `discoverSchoolPages(school: string): Promise<{ title: string; url: string }[]>`。
- 复用 `src/lib/ai/summarize.ts` 里 `chatJson` 的调用模式（同一套 `DEEPSEEK_API_KEY` / base / model），发一条 `system` 指令让模型输出 JSON 数组 `[{title,url}]`：为该校列出获取校园新闻相关的网页（官网、新闻网、院系、研究生院、招生网等），最多 15 个，只给真实可访问页面，不确定不编造。
- 无 AI key 或调用失败返回 `[]`；结果里对 URL 做基本校验与去重。

### 4. 改 `src/app/api/school/route.ts`
- 去掉 `SCHOOL_OPTIONS` 白名单校验；改为：`school` 非空字符串（trim 后）即合法，写入 `configs.upsert({ user_id, school })`。

### 5. 新 API 路由
- `src/app/api/discover-sources/route.ts`：`POST { school }` → `discoverSchoolPages(school)`；同时返回当前用户已有来源 URL 集合，供前端标记「已添加」。
- `src/app/api/sources/route.ts`：
  - `GET` → 当前用户 `sources` 列表。
  - `POST { name, url }` → 校验 name 非空、url 为 http/https，`insert`（靠 `unique(user_id,url)` 与 RLS 防重/防越权）。
  - `DELETE`（query `?id=`）→ 删除本人来源。

### 6. 改 `src/lib/crawler/fetch-source.ts`
- 用「单页抓取」替代现有列表页多链接抓取核心：新增 `fetchSourceUrl(url: string, name: string, opts): Promise<FetchedArticle[]>`——`fetchText(url)` → `parseDetail(html)` → 返回单条 `FetchedArticle { source: name, url, title, published_at, raw: { text } }`。
- 保留 `FetchedArticle`、`FetchSourceOptions` 字段含义（`knownPublishedAt` 仍用于复用已入库 URL 的日期）。
- 旧的 `fetchSource(Source, …)` 与 `parseListLinks`（仅 `fetch-source.ts` 引用）不再使用，删除；`parseDetail`、`fetchText`、`sleep` 保留复用。

### 7. 改 `src/lib/pipeline/run.ts`
- 删除 `SOURCES` 导入；读用户来源：`supabase.from("sources").select("*").eq("user_id", userId)`，得 `srcs: {id,name,url}[]`。
- 空来源时：直接产出「空来源」运行记录（`status="failed"`，`empty_reason="未配置来源"`），不抛异常。
- 来源循环改用 `srcs`：
  - `source_runs` 插入 `{ user_id, run_id, source: src.id, name: src.name, status:"pending" }`。
  - `fetchSourceUrl(src.url, src.name, { cap, knownPublishedAt: known })`。
  - `sourceResults.push({ source: src.id, name: src.name, status, items_count, error })`。
- `items.source` 写 `src.name`。
- 其余（标准化、去重合并、分类、AI 总结、日报、run_locks）不变。

### 8. 可信度判定 `src/lib/ai/summarize.ts`
- `inferCredibility` 由「按硬编码 key」改为「按 URL 域名」：any 来源 URL 的 host 以 `.edu.cn` / `.ac.cn` / `.gov.cn` 结尾 → `官方事实`，否则 `传闻待证实`。
- `run.ts` 中 `inferCredibility(c.sources)` 改为 `inferCredibility(c.source_urls)`（URL 才是稳定信号）。

### 9. 展示侧映射（来源名不再靠 `sourceByKey`）
- `src/lib/agent/tools.ts`：`getRunStatus` 的失败来源名改为 `s.name ?? s.source`；`updateConfig` 工具的 schema description 去掉「学校固定北华航天工业学院、不可修改」。
- `src/lib/agent/chat.ts`：系统提示词里的「服务学校：北华航天工业学院（固定不可改）」改为「学校由用户填写」；`buildContextText` 里学校行改为 `cfg.school ?? "（未设置）"`。
- `src/lib/mail/deliver.ts`：`MailSourceStatus.name` 改用 `s.name ?? s.source`；`render.ts` 里 `wrap()` 硬编码的学校名去掉（改为不写校名，或由参数传入，取简单方案：去掉校名）。

## 前端改动

### 1. `src/components/select-school/select-school-form.tsx`（重写，两步引导）

- 第二步：自动调 `POST /api/discover-sources { school }` 展示候选网页（标题 + URL，勾选框，标记已添加项）；支持「手动添加一个 URL（名称+URL）」；「保存选中来源」批量 `POST /api/sources`，缺省也可「跳过，稍后设置」；完成后 `router.push("/")`。

### 2. `src/app/select-school/page.tsx`

### 3. `src/app/page.tsx`

### 5. `src/components/dashboard/settings-tab.tsx`

- 「说明」区块去掉「仅支持北华航天工业学院单校」等过时文案。

## 验证方式

1. 手动在 Supabase SQL Editor 执行 `supabase/migrations/00005_add_sources.sql`（建 `sources` 表、`source_runs.name` 列、RLS）。
2. `npm run dev`，用 demo 账号登录 → 应进入 `/select-school` 引导页（首次）→ 输入任意学校（如「清华大学」）→ 看到 AI 生成的候选网页 → 勾选并保存 → 进入首页。
3. 首页「立即运行一次」→ 应读取该用户来源而非硬编码 4 校来源，`runs` / `source_runs` / `items` / `digests` 正常生成；设置页能看到来源状态与来源管理。
4. 设置页手动新增一个来源 → 再次运行验证抓取到该 URL；删除来源 → 运行验证其不再参与。
5. `npm run lint` 与 `npm run build` 通过（关注删除 `SOURCES`/`sourceByKey`/`SCHOOL_NAME` 后的残留引用）。
